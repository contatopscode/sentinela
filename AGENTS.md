# Regras de ouro

1. Nenhum código, nome, dado ou exemplo de empregador ou cliente do Paulo no repositório, nem no histórico.
2. Nenhum segredo no código, nos testes, nos exemplos ou no histórico; `.env.example` só com valores de mentira.
3. Tudo configurável por variável de ambiente; nenhum nome de modelo ou URL fixo no código.
4. Todo o projeto roda e testa sem chave de API, com o classificador `fake`.
5. Nunca inventar endpoint, nome de modelo ou função de biblioteca; consultar a documentação oficial ou perguntar.
6. Cada fase termina com testes passando e parada para revisão.
7. Commits pequenos, com mensagem clara em português.
8. Python 3.11 ou superior, tipagem completa, `ruff` e `mypy` limpos.
